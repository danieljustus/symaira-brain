## Decisions and reasons

1. Keep one original eleven-tool order, shared by catalog and raw-transport admission: library, profiles, render, versioning, status. CoreKit emits registration order. Transport recognizes the exact names, without enabling a server or expanding policy exposure. No transport→Skills dependency or generic registration framework is introduced. Disabled Skills still routes to the existing unknown-tool response. Other tools retain the old whole-Value envelope/params admission and error mapping.
2. The six report renderers return the first writer failure with Go's subcommand context. Read and sync happen before reporting; a sink failure never rolls back completed work. Help and stderr retain their existing separate handling. The library's injected writers do not own process signals. `run_stdio` alone selects a Skills fd1 wrapper, which emits Go's stdout PathError label and only after actual Unix OS EPIPE invokes the already pinned signal-hook default SIGPIPE completion. There is no global reset, new dependency or Windows signal claim. The existing version function was moved with its body unchanged to keep the edited dispatcher below400 lines.
3. Known Skills requests retain RawValue params/arguments through the actual Decoder→Gateway→Skills boundary before recursive Value parsing. The ordered anonymous-struct decoder uses the existing Go string repair for both values and keys, preserving duplicate fields and unknown numeric tokens. Known overflowing integer fields remain errors; ignored numeric fields are not converted to float64. Audit receives Go-repaired string tokens through the existing shared float64/overflow/redaction owner; no redaction is disabled and no raw sensitive material is logged as a fallback. Existing byte/frame limits remain.
4. Discovery observes Lstat once before classifying a root. Missing paths get their operation/path diagnostic; ordinary explicit files are omitted; dangling links reach the actual bounded ReadDir failure. There is no panic from guessing metadata failure using `exists()`. Source IDs, target preference and ordering remain. Bounds and capability refusals are not weakened.
5. Library entries use a confined per-bundle directory and the existing shared actual-read budget, so document labels are `SKILL.md` and ordinary open errors include `openat SKILL.md`. Only real directory entries are admitted, as Go's DirEntry.IsDir specifies. A small private filesystem error presentation helper separates the actual operation/path from host errno text; it does not convert a read failure into absence or suppress special-file/resource-bound errors. Newly admitted ordinary errors still require actual native3 process proof.
6. Git archive stdout and stderr have separate bounded file captures. Only stdout reaches the confined tar reader; archive failure uses only stderr and Go's `git archive <rev>` context. Other Git operations retain combined output. Both channels share the existing total byte limit and immediate-child cleanup owner. On Unix the discovered spelling is argv0, rather than forcing the bare `git` spelling. Actual Windows owner/argv0, batch and raw-path behavior remains a required observation, not a waiver.
7. A pair and each live process row enter the report before invocation/comparison can throw. RPC error objects keep their complete error branch; malformed comparator input records a structured exception and cannot certify the gate. Fixture commands retain timeout/launch failures and partial streams. Actual mutation-control records are saved before comparing. Reporting does not transform a bootstrap failure into a successful negative control.
