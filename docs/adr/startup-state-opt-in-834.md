# Startup state and history opt-in (#834)

**Status:** approved target contract. **Foundation:** exact PR #813 base `2f6880815a4aa65c4a2d7810240ef0cfd1effe4d`. This contract changes the candidate only; the immutable Go oracle at `dcddcef0df5789123c7c9a7ebe6e01f10e941f2c` and its captured filesystem effects remain unchanged.

## Effective startup rules

- A disabled profile memory core is absent before memory configuration, SQLite, or JWT initialization. It creates no memory database, authentication key, or memory startup directory. An enabled profile continues to expose and initialize the native memory implementation; Rust does not create the legacy Go JWT key.
- Audit is enabled only when both the selected profile and the resolved global `audit.enabled` setting enable it. A profile opt-out is authoritative even when the global configuration defaults to enabled; a global opt-out also vetoes a profile opt-in. Rust validates TOML and the configured `audit.enabled` value before applying `SYMBRAIN_AUDIT_ENABLED` and before starting child backends. A valid environment override, or a disabled profile, cannot suppress a file error. Missing files still permit overrides. The Go loader ignores a non-table top-level `audit` section; this is not an invalid `audit.enabled` value, and Rust preserves that distinction.
- Episode capture is metadata-only and explicitly opt-in. Go `patterns.enabled` defaults to false; a TOML or environment `true` enables capture, `false` disables it, and an absent setting does not create an episode file. The existing read-only `patterns` tool and the on-disk history schema remain unchanged. Rust receives no copied Go episode writer under this issue.

These rules govern Brain capability/startup state only. They do not add Guard per-call conduct policy, authorization prompts, or approval behavior.

## Legacy/target acceptance boundary

The frozen Go process is expected to retain its historical startup behavior: memory initialization is unconditional, audit is enabled by either profile or global config, and absent `patterns.enabled` defaults to recording. Those observations are evidence, not desired parity. The native target uses profile-gated memory, profile-and-global audit, and no automatic history capture.

`scripts/skills-native-oracle/startup_controls.py` adds five actual Go/Rust process pairs: profile audit opt-out against global opt-in with absent history config; explicit audit and history opt-ins; global audit veto; explicit history false; and enabled-memory positive control. It retains raw stdout/stderr/exit/PID and complete filesystem entries/modes/raw file SHA-256 observations. The classifier accepts only the named startup-owned paths (`config/symbrain/memory`, `data/symbrain/memory`, `data/symbrain/audit`, and `data/symbrain/recipes`) after checking each case's exact owner/profile-derived presence, absence, type, private file mode, shared-path modes, and legacy Go file evidence. The Rust target must have no disabled-memory key/database, no disabled audit log, and no episode history. Any other file, mode, link, response, or filesystem difference remains a failure; Skills cache/render contents and hashes are never projected away.

The ordinary Skills MCP matrix, permission-denied MCP pairs, and byte/JSON/EOF input controls use the same startup classifier through `ordinary_startup.py`. Admission is bound to the exact `skills-native-764` fixture (including the Skills-disabled variant), absent global configuration, absent startup environment overrides, and the unchanged frozen Go revision. Only the exact profile-derived startup files/directories and the necessary Go JWT ancestor `config/symbrain` are projected in temporary comparison views after presence, absence, type, privacy, raw hash and owner checks. There is no subtree exclusion or cache prewarming. Requests rejected before reaching a wrapped handler and transport parse errors do not create a Go episode; the already-open Go audit file may be empty in those cases. Errors returned by a wrapped handler still record a Go episode. Raw observations are never modified. The complete MCP catalog and every response field, exit and stderr remain compared; actual-input controls may change only the third response, not initialization or the full tool catalog. `compare.py`, `json_compare.py`, all original wires, and Skills cache/marker/hash assertions remain unchanged.

On Unix, existing strict POSIX privacy/mode checks remain. On Windows, `startup_privacy.py` obtains owner and raw DACL observations through native PowerShell/.NET ACL APIs, retaining the descriptor, ACE types/flags/masks/SIDs and probe stdout/stderr before validation. The owner must be the current user; only that user, SYSTEM and Administrators may receive allow ACEs. Null/empty DACLs, broad or inherited non-private grants, unknown ACE types, missing owner read/list access and incomplete probes fail closed. Windows `st_mode` is not accepted as privacy evidence. These conservative assertions can expose inherited ACL defects; they do not waive the Windows gate or repair permissions behind the product's back.

The process controls and Rust integration regressions are source-prepared here. Focused Python controls are explicitly synthetic structural tests, including the Windows policy branches, not native evidence. A local diagnostic can exercise the comparator against actual frozen-Go and candidate-Go processes, but must label both implementations accurately and must not count as Rust/native acceptance.
