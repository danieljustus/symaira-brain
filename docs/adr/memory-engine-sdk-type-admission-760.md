We require two explicit phases. First, both whole SDK roots pass a no-follow filesystem census and the fixed file/directory names and permission modes. Only after both roots pass may any SDK byte reader run. Missing or added inputs, aliases, special files and changed modes are fatal admission errors. This ordering prevents a malformed second SDK from allowing reads of the first. The whole-root map is still fixed; the helper never generates or widens it at admission. The independently required 7,947 legacy hashes are then checked against the already observed checked-descriptor hashes, rather than opening legacy paths again. This preserves the old byte bindings without the old unsafe opening order.

The byte reader checks `lstat`, opens read-only with POSIX `O_NONBLOCK` and `O_NOFOLLOW` where available, checks the opened descriptor's regular-file type and exact device/inode/mode identity against that observation, hashes only that descriptor, and closes it on success or failure. Expected permission mode is also checked before opening. This protects the concrete leaf substitution boundary: an owned FIFO swapped after `lstat` cannot block opening, a swapped leaf symlink is refused, and a different regular file is refused before reading. There is no child invocation, signal policy, recursive cleanup or timeout inflation in this correction. The general source/receipt digest helper remains outside this narrow SDK correction.

This is an input admission boundary, not a cryptographic guarantee against concurrent mutation of an SDK during compilation. Exclusively owned, stable input roots and the existing before/after build and before/between/after replay checks remain required. The installed SDK map admits Linux x86_64 only. POSIX descriptor controls are actual Linux filesystem proofs; the optional availability of similarly named flags on other platforms is not native Windows/macOS runtime evidence. A future platform map needs its own actual safe-open and complete native build acceptance.
