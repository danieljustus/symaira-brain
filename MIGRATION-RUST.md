### Skills config TOML decode foundation (#764 slice f, SKL-018)

Every config-file shape of `skills status/doctor/list/sync` still routes to Go because
no Rust decoder reproduced Go's TOML handling. `symbrain_skills::config_toml` is that
decoder; this slice delivers it, its Go oracle and a negative-control runner, and **does
not change CLI routing** (the consumers in `skills_cli.rs`/`skills_doctor_config.rs`
still treat any config file with content as Go).

Go reads the files in two independent ways, both reproduced:

- `config.Load` (corekit `configkit.mergeFile`): `toml.DecodeFile` (BurntSushi/toml
  v1.6.0, TOML 1.1) into `map[string]interface{}`, then an exact, case-sensitive copy by
  `json` tag in struct order `library_dir`, `render_dir`, `cache_dir`, `profiles_dir`,
  `base_dir`, `vcs`. A non-string value is `field "k": cannot convert <%T> to string`
  (`int64`, `float64`, `bool`, `time.Time` for all four datetime kinds, `[]interface {}`,
  `map[string]interface {}`, `[]map[string]interface {}` for `[[k]]`); a non-table `vcs`
  is ignored silently; `vcs.enabled` accepts a bool or a `strconv.ParseBool` string
  (`field "vcs": field "enabled": cannot parse "yes" as bool: strconv.ParseBool: ...`).
  The first failing file ends the load: `global config error: failed to apply <path>: ...`,
  then `project config error: ...`. `targets` has no `json` tag and is skipped here.
- `config.LoadTargets`/`LoadCapabilities`: typed `toml.DecodeFile` into `targetsFile`
  with case-insensitive field folding (`strings.EqualFold`, so U+017F and U+212A fold to
  `s`/`k`), `[[targets]]` or an inline array of tables, a `map[string]bool` that
  silently ignores a non-table value (and a `capabilities.<t> = true` creating an empty
  `<t>` map), per-file merge (non-empty `targets` replaces, capabilities merge per name).

Decisions:

- **Parser = `toml_edit` plus post-checks**, not a hand-written grammar. The result is a
  three-way classification: `Loaded`/`Error` only when the replay proves Go agrees, and
  `NeedsGo(reason)` for everything else. Every syntax error, invalid UTF-8, typed-decode
  type error (messages embed TOML key paths and lines) and every document Go decodes
  differently is `NeedsGo`; Go keeps owning those messages.
- Post-checks found by the oracle (documents `toml_edit` accepts and Go rejects): a
  second leading BOM, the `:60` leap second (any datetime anywhere in the document) and
  multi-line inline tables (BurntSushi tolerates a newline only after `{`, after a comma
  and before `}`, `toml_edit` also between a key and `=`).
- Known Go-accepts/Rust-asks-Go set (28, pinned in the test): BurntSushi lets a value
  redefine a dotted table or a table extend an inline table, accepts datetime offsets
  `+24:00`/`+00:60`, has no `toml_edit` nesting cap, and `%q` of a non-ASCII `vcs.enabled`
  string is not reproduced. Two typed-decode cases are map-iteration-order dependent in
  Go (two keys folding onto one field); the generator repeats each typed decode 40 times
  and records such a case as `nondeterministic`, which Rust must send to Go.

Evidence: `scripts/skills-config-toml-oracle` runs the real `config.Load`,
`config.LoadTargets` and `config.LoadCapabilities` over 6769 cases in a disposable
HOME/cwd (one per line in `rust/symbrain-skills/tests/fixtures/config_toml_oracle.json`;
`make skills-config-toml-oracle-check` regenerates and compares, ignoring provenance).
`tests/config_toml_oracle.rs` replays it without Go: 1262 `Load` values and 188 exact
apply errors native, 5291 Go parse errors left to Go (never answered natively), plus 1417
native typed decodes. A soak mode (`SYMSKILLS_CONFIG_TOML_ORACLE_FIXTURE`, generator
`-out/-mutations/-seed`) replayed two further seeds of 40769 cases each (81538 cases) at the final code with
zero mismatches.
`scripts/skills-config-toml-oracle/mutants.py` applies 16 single-line mutants of
`config_toml.rs` (type names, ParseBool spelling, BOM, leap second, multi-line inline
table, inline `vcs`, error label, both fold characters, collision, empty-targets
override, capability merge, non-table map, `%q` width): 16 of 16 killed.

Residual: routing. `skills_cli.rs`/`skills_doctor_config.rs` must still (1) read the
config bytes through the same stat/`os.IsNotExist` gates, (2) call `config_toml::load`
and fall back on `NeedsGo`, (3) apply `SYMSKILLS_*` and the discard-to-defaults rule, and
(4) for `status`/`list`/`sync` feed `LoadTargets` into the native verbs, each with its own
Go-vs-Rust differential. Native three-OS CI at the final head remains required.

#### Review fixes: unbounded nesting and dotted-key cost (#769 slice 2)

Independent review found that Go (`encoding/json` Decoder, BurntSushi/toml)
accepts any nesting depth below the 8 MiB cap while the Rust port recursed on
the native stack, and that long TOML dotted keys were cubic. Fixed in
`symbrain-harness`:

* `go_toml/parser.rs`: `Parser::value` walks arrays and inline tables with an
  explicit frame stack instead of recursion; `Value` has iterative `Drop`,
  `Clone` and a non-recursive `Debug`. A 100,000-deep array, an unterminated
  one, and 1,500-deep inline tables no longer overflow a 256 KiB test stack.
* Dotted keys: key components are shared (`Rc<str>`), the context is truncated
  instead of cloned per component, and `setValue`/`addContext` descend the
  mapping once instead of re-walking it from the root per path element. A
  1,000-component key went from 36.7 s to 0.02 s (release); 30,000 components
  take 28.8 s against 36.1 s in Go (both are quadratic in Go's algorithm).
* `json.rs`: `marshal` writes nested documents with an explicit stack (the
  `go_json` decoder and the JSON `Value` drop were already iterative).
  `install -dry-run`/`uninstall -dry-run` of a 100,000-deep JSON config now
  match Go (stdout, stderr, exit) instead of aborting with a stack overflow; a
  real install of that config is refused by the 8 MiB output cap (residual 2).
* `go_read.rs`: directory components are walked as raw bytes, so a parent
  directory whose name is not UTF-8 is opened by its real name (the lossy
  conversion looked for a different, absent directory). The unit test cannot
  create such a directory on APFS and returns early there; it only runs on
  file systems that accept non-UTF-8 names.

The oracle gains 8 deep/long-key TOML shapes (16 cases: 940 parity cases pass)
and `go_parse_errors` gains four small-stack cargo tests that overflow or hang
without the fixes. Residuals, all measured and unchanged by this fix: (1) for
codex `install`/`uninstall`, `toml_edit` (the format-preserving edit backend)
refuses nesting deeper than 80 levels, the same limit the doctor-repair README
records: depth 80 is accepted and 81 refused for arrays, inline tables,
dotted-key components and table-header components alike (arrays of inline
tables: 40 pairs accepted, 41 refused). Rust then exits 2 with `not valid toml;
refusing to edit` and leaves the file untouched, where Go exits 0 and edits;
`harness list` is exact at any depth; (2) JSON
output above `MAX_CONFIG_BYTES` is refused on write by Rust while Go writes it
(18 MB output of a 3,000-deep config); (3) inline tables nested inside arrays
stay super-linear (12,000 levels: 43.9 s vs 13.8 s in Go, 3,000 levels: 3.0 s
vs 1.2 s) because Rust clones the finished subtree where Go shares the map;
no crash, identical output, and far less memory than Go.

### `memory sync` loopback exchanges without a Go fallback (#762 slice 2)

Slice 1 left every valid invocation on Go. The sync client now runs natively
for the exchanges whose whole behaviour is proven against the shipped client;
everything else is handed to Go. `memory_cli::requires_go_fallback` no longer
gates `sync` (only `serve`): `memory_cli::run_sync` decides, and returns `None`
to hand an invocation to Go with nothing written to the output streams.

Native subset (`sync_native.rs`, `sync_http.rs`, `sync_decode.rs`; store side
in `symbrain-memory/src/sync_state.rs`):

* plain mode against `http://127.0.0.1:<port>[/prefix]` only (explicit port,
  not 80, no leading zero; prefix segments `[A-Za-z0-9._-]`, never `.`/`..`/empty;
  no query, fragment or userinfo; lower-case scheme), `--pull`/`--push`/both,
  `--json`/`--output`, `--allow-insecure-http` (the shipped warning is printed
  after the database is opened, in the shipped order), `--token`/
  `SYMBRAIN_MEMORY_SYNC_TOKEN` for printable ASCII without spaces, `--timeout`
  of `Ns` (1..=60) or `1m` (default 60 s). The database is opened (created and
  migrated) before any network traffic, as in Go.
* request: one `GET <base>/api/sync/changes?limit=500[&since=<cursor, UTC,
  whole seconds, ':' as %3A>]` with exactly the headers Go sends (`Host`,
  `User-Agent: Go-http-client/1.1`, `Accept-Encoding: gzip`, `Authorization:
  Bearer ...` when a token is set; no `Accept`), no proxy, no redirects. A push
  half sends nothing when nothing is pending: the probe uses the shipped
  predicates (`updated_at > cursor` without `sync_exclude`; latest oplog entry
  a newer delete) with the shipped bound rendering.
* replies: statuses above 300 print `remote returned <code> (<status>): <msg>`
  or `remote returned status <status>: <msg>` from the first JSON value of at
  most 64 KiB (case-insensitive `error`/`code` keys, last duplicate wins,
  non-string values and non-objects leave the field empty, truncated or stalled
  bodies decode as far as they were read); 300 and 2xx are decoded as a
  `ChangesResponse`: `{}`, `null`, empty `memories`/`deleted`, empty or null
  `next_cursor`, unknown keys and a `server_time` of
  `YYYY-MM-DDTHH:MM:SS[.f]Z` (zero time allowed) are an empty exchange; an
  empty body prints `decode remote response: EOF`, a leading non-value byte
  `invalid character 'x' looking for beginning of value` (Go `quoteChar`
  rules), a truncated value `unexpected EOF`; a short body reports
  `unexpected EOF`, a stalled one `context deadline exceeded`.
* transport: connection refused (POSIX wording) and the run deadline
  (`Get "<url>": context deadline exceeded`, also for a header stall or a
  silent 1xx).
* effect: the cursor becomes the relay clock (`max(server_time, zero)`), stored
  as `YYYY-MM-DD HH:MM:SS[.nnnnnnnnn] +0000 UTC`; a push-only run reports no
  relay clock and therefore stores the zero cursor (the shipped quirk, kept); a
  failing exchange leaves the cursor untouched. Stored cursors in any other
  spelling (the shipped driver cannot read them either) go to Go.

Handed to Go (`None`), each proven by a scenario: https, `localhost`, any other
host or loopback address, the encrypted relay, tokens with spaces or non-ASCII,
timeouts outside the claimed spellings, unreadable stored cursors, pending
local memories or tombstones (the push half), and, after the first read-only
GET, any reply that carries memories, tombstones or a pagination cursor, a
`server_time` in another spelling or with a bad value, non-object or wrongly
typed JSON, folded (`Server_Time`) keys, bodies of 1 MiB and more, nesting

### `memory sync` pulls that carry data without a Go fallback (#762 slice 3)

Slice 2 handed every reply with memories, tombstones or a pagination cursor to
Go. The pull half now applies them natively, over any number of pages, with the
shipped `SyncUpsertMemoryIfNewer` / `ApplyRemoteDelete` semantics. Everything
that is not proven below still reaches Go, and always before the first local
write.

* Request: unchanged for the first page; later pages send
  `GET <base>/api/sync/changes?cursor=<url.QueryEscape(next_cursor)>&limit=500`
  (no `since`: the cursor takes precedence, keys in `url.Values.Encode` order).
  A `next_cursor` of at most 2048 bytes is echoed; more than 64 pages go to Go.
* Entries (`sync_entry.rs`, a `db.Memory` / `db.DeletedMemory` reading): objects
  whose known keys are spelled exactly (a case-folded or repeated known key is
  not claimed) and typed as the shipped decoder reads them: strings without NUL,
  `null` as the zero value, `Z`-spelled times (`created_at`, `updated_at`,
  `valid_*`, `expires_at`, `retired_at`, `last_access`, `prev_access`),
  `importance` / `decay_factor` as finite `float64` literals, `access_count` as
  an `int64` literal, `metadata` as `null` or an object of strings, `embedding` as
  absent, `null` or `[]`, `entities` / `evidence` only when they are `null`, empty
  (or, for `entities`, strings). A missing or empty `id` is not claimed; unknown
  keys are ignored (JSON syntax only). Tombstones need a string `id` and an
  optional `deleted_at`.
* Application (`symbrain-memory::sync_apply`): one transaction per run, memories
  before tombstones page by page, applying the shipped SQL: tombstone check
  (`sync_oplog` latest row `delete` and `updated_at <= ts` skips), insert with
  the shipped defaults (`consolidation_status` `raw`, `review_status`
  `approved`, `decay_factor` outside `(0,1]` -> `1`, `content_hash` computed when
  empty, nil metadata `null`, NULL for empty `consolidated_into_id` /
  `superseded_by`, no `embedding_binary`, `lsh_hash` 0) or update (strictly newer
  only; `created_*`, `valid_*` and `superseded_by` stay), the best-effort
  `audit_log` rows (`set` / `update` / `delete`), and `ApplyRemoteDelete`'s
  `local updated_at > deleted_at` guard. Times are stored as `YYYY-MM-DD
  HH:MM:SS[.nnnnnnnnn] +0000 UTC` (nanoseconds, trailing zeros trimmed, as the
  cursor is). A stored `updated_at` / oplog `ts` in any other spelling than the
  driver's own or the oplog trigger's `...T...fffZ` is not claimed.
* Effect: counters `pulled_memories_applied` / `pulled_deletes_applied`; the cursor
  becomes the newest of every `updated_at`, `deleted_at` and `server_time` of all
  pages (`maxSeen`); all pages are fetched before anything is written. If page
  `k` fails with a proven wording (error status, decode failure, short or stalled
  body, deadline) pages `1..k-1` are applied, the failure is printed and the
  cursor stays, exactly what the shipped client leaves behind.
* Both directions: after the pull the push stream is probed with the shipped
  predicates (`updated_at > cursor` without `sync_exclude`; latest oplog entry a
  newer delete). A pull that would make the shipped client push (`/api/sync/apply`)
  is rolled back and handed to Go; data older than the stored cursor, excluded
  memories and pulls that failed (the shipped client stops before pushing) stay
  native.

Handed to Go with the batch rolled back (the scenario proves no memory, audit,
oplog, entity or cursor row differs afterwards): malformed or unproven entries
(null / non-object entries, wrong types, offset or odd time spellings, year 0,
folded / duplicate keys, non-empty embeddings, NUL, lone surrogates, invalid
UTF-8, control characters inside strings), a repeated `memories` / `deleted` /
`next_cursor` key that carried data, cursors above 2048 bytes, more than 64
pages, redirects / gzip / closed connections on a later page, a statement the
store rejects (for example a `consolidated_into_id` without a parent, where the
shipped client keeps the memories applied before it), and a pull that provokes a
push. The shipped client then repeats the read-only `GET`s.

### `memory` store creation and `sync` dead route without a Go fallback (#769 slice 4)

Three Go routes are gone. (1) `sync_cli::requires_go_fallback` was a constant
`false`; the `"sync" if ... => None` arm in `lib.rs` is removed. (2) `memory`
no longer keeps Go when the database path cannot be created: `Store::open`
now reproduces `sqlitekit.Open`'s `SafeMkdirAll(dir, 0700)` (`store_dir.rs`):
`filepath.Dir`/`Abs`/`Clean` semantics (`d/` and `a/../b` included), a
root-to-leaf walk, mode `0700` under the process umask, existing directories
untouched, non-root-owned symlinks refused with `too many levels of symbolic
links`, non-directories with `not a directory`, and `mkdir PATH: <errno>` text
from the platform `strerror` (lower-cased like Go's errno table). A failure in the
connect phase (file open plus the busy-timeout, foreign-key and WAL pragmas the
Go DSN applies on its first ping) reports Go's doubled `failed to open sqlite
database: failed to open sqlite database: <fixed SQLite description> (<primary
code>)`; later-phase errors (secure-delete, migrations) are not remapped. Every
memory verb now prints Go's `symbrain memory <verb>: open memory database: ...`
prefix instead of the earlier Rust-only `symbrain memory: open database:`.
(3) `set`/`delete` (and the reads) on a database path that does not exist, or
exists but is not a regular file, are native: a fresh store has no rows to
hydrate, so no Go admission applies; directories get `0700` and the new
database `0600`, as in Go. Non-regular existing paths (`/dev/null`, a FIFO)
are opened by SQLite without blocking and fail while connecting; the native
opener maps that to Go's doubled wording, so no routing exception is needed.
The printed SQLite code depends on the environment, and Go and Rust agree in
each one (live replay): `/dev/null` is `unable to open database file (14)` on
the local macOS 27 host but `attempt to write a readonly database (1544)` on
Linux as a non-root user (and on the GitHub macOS runner, where the failed
check showed the masked `(8)`); a FIFO is `disk I/O error (10)` on macOS and
Linux. The rule behind the codes: the shipped driver enables SQLite extended
result codes only after `sqlite3_open_v2` returned, so a failure inside the
open call (FIFO header read, directory as database) prints the primary code,
while a failure of the DSN pragmas that follow (busy-timeout, foreign keys,
WAL) prints the extended code SQLite returned (`1544` =
`SQLITE_READONLY_DIRECTORY`). `go_open_failure` takes the phase for this
reason; `rusqlite` enables extended codes for the open call as well, so the
open phase masks to the primary code. Native `cargo test` pins only the shape
`<text> (<code>)`, never a code list. A directory as database
path keeps `unable to open database file (14)`. A regular non-SQLite file under
`set`/`query-log` now also prints Go's doubled `file is not a database (26)`.
The code rendering is proven only for these observed cases (and read-only
DELETE-mode `(8)`, malformed `(11)`). Go prints a suffix in other
connect-phase cases, which is not claimed: a locked database gives Go
`(5) (SQLITE_BUSY)` versus Rust `(5)` (Rust also waits about 11 s against Go's
5 s). A WAL database in a read-only directory is a pragma-phase failure like
Linux `/dev/null`, so the phase rule above now renders its extended code
`1544` too; that scenario is not in the replayed families.
