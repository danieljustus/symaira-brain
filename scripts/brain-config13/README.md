# Prepared Brain typed configuration gates

These fixtures are source preparation. No successor executable has been built
and none of these gates has been run at the precompile checkpoint. Their strict
comparisons are expected to expose the explicitly open parser/discovery and
separate eager-Memory acceptance gaps until those contracts are completed.

`process.py` contains102 CLI case definitions: the original91 typed consumer and
ordering cases plus11 syntax boundaries. It captures complete stdout/stderr bytes,
exit, filesystem modes/content/link targets and owned local HTTP requests. Its
default mode supplies a nonexistent Go binary to the native CLI. The optional
fallback mode is a preparatory route census and cannot prove native acceptance.
The original24 boundary/pattern/admission groups, all115 census groups and all269
actual original executions remain bound by the tracked initial retention receipt.

`values.py` contains152 Unix /174 Windows loader case definitions. It compares the
actual13 resolved values through dedicated Go/Rust probes, without constructing
Memory/JWT, providers or children. Strings and the selected config path are
represented by hexadecimal bytes, preserving raw Unix and Windows WTF8 values.
Every output byte, exit and owned filesystem state is compared; there is no
diagnostic parser projection. This isolated value proof complements full consumer
proof and cannot substitute for it.

`stage_go.py` only copies the receipt-verified frozen production config source and
Go module files into a new owned directory, then adds `go_probe.go`. It refuses
an existing destination or one inside the frozen source. It does not build. The
future build must use the pinned SDK, offline existing modules, a source manifest
and an actual executable SHA; original Go sources and fixtures remain unchanged.

After central compiler/target allocation, build the Rust example in the same
exclusive target as the candidate CLI. Run each gate under the established
subreaper, `set -euo pipefail` and umask022, with the exact clean candidate source
root/HEAD and selected executable paths. Each run needs a new output receipt/log;
retain failed attempts without overwriting earlier files. No embedding endpoint,
operator HOME or external release endpoint is used. Actual raw Windows UTF16,
SDK path/lookup ownership, signal/descendant, stderr/stdio and embedded writer
controls remain required alongside these portable cases.

The complete parent/fresh consumer/lifecycle/control/native3 gate plan is in
`migration/evidence/brain-config13/precompile-plan.json`. Counts under
`parent_actual_*` describe the retained parent only. Prepared case counts and
static checks are not runtime results or independent approval.

`brain_config13_fault` is a prepared actual-process control executable. It delegates
the selected candidate, then deliberately injects an owned loopback request or
owned file after fatal admission, changes an exit/type error, or flips a resolved
value. Selected-case control runs must demonstrate strict gate rejection and
preserve full output/state/request evidence, with both wrapper/delegated SHAs.
No control has been built or run in this checkpoint.
