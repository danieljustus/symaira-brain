# Reclaim completed source worktrees while retaining reproducible decisions

The shared workspace approached its storage floor despite prior cache retirements. Cache removal on a lower filesystem overlay had sometimes reclaimed no space. Duplicated completed source worktrees were a separate, measurable source of storage pressure.

Decision: retire only specifically reviewed obsolete worktrees whose exact committed source and full tracked raw proofs are verified against locally present Git blobs, whose branches remain persistent and whose heads are strict ancestors of an accepted published checkpoint. Preserve Gitrefs/objects, full tracked byte/hash/native-permission manifests and explicit restoration commands. Keep current published heads, prepared current candidates, active source paths, frozen oracle worktrees and all targets/shared caches outside this operation. Native0600/0700 permissions from prior private umasks are recorded without confusing them with Git's executable-bit identity.

Immediately before each normal removal, require fresh clean/index/untracked/ignored checks, no target/runtime cache, source/proof identity, stable branch/head and no visible process consumer. Only demonstrated CPython derivative caches may be cleared, with their original bytes retained. Never use --force to hide an unknown file. Record and fsync exact commands, outputs, failures and measured free-space changes. Stop once the requested scheduling budget is reached; don't remove every candidate automatically. Future allocations must inspect current free space again.

Root explicitly accepted the bounded observation that privileged host dockerd/containerd process references were unreadable to uid1000 while visible agent references and running Docker containers were zero. Preserve these two UNVERIFIED services separately; don't manufacture a global process-zero guarantee or an extra user-approval requirement. This is routine reversible source-worktree retirement, not deletion of branches, code, evidence or operator data. A removed source path can be restored from its retained branch with normal git worktree add and the saved native-mode manifest.

Actual outcome: ten of15 approved worktrees removed; at stop2.620GiB available, measured increase1.905GiB. Five remain. A later snapshot after two concurrent new worktree registrations showed2.330GiB available. No compiler, target, port, product or GitHub mutation was involved.
